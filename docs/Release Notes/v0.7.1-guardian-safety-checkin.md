## Overview

Task 7 delivers the complete **Guardian Safety Check-In Engine** — RidePulse's peer-monitored ride safety layer. Guardians are trusted RidePulse users who monitor rider safety via a structured check-in schedule. If a rider misses a check-in, the system automatically escalates through 4 stages.

## Database Schema

### Guardian
- `riderId` + `guardianUserId` (unique compound index)
- `permissions[]` (7 permission types)
- `priority` (1–10, lower = first notified)
- `isActive`, `totalSessionsMonitored`, `totalCheckInAlerts`

### GuardianInvitation
- Token-based with TTL index (72h)
- Status: `PENDING | ACCEPTED | REJECTED | EXPIRED | CANCELLED`
- `requestedPermissions[]`, `priority`, `message`

### GuardianSession
- `windows[]` — array of `ICheckInWindow` with grace deadline
- `intervalMinutes`, `gracePeriodMinutes`
- `escalationStage` (0–4)
- Status: `ACTIVE | COMPLETED | ABORTED | EXPIRED`

### GuardianActivity
- Immutable append-only log
- 14 activity types tracked
- Used for analytics and audit trail

## Escalation Workflow

```
Rider misses check-in
       ↓
Stage 0 → Grace period starts (gracePeriodMinutes)
       ↓
Stage 1 → Rider gets Socket.IO reminder (guardian.missed)
       ↓  (still no response)
Stage 2 → Guardian receives alert (guardian.missed)
          + GuardianActivity log: CHECKIN_MISSED
       ↓  (still no response)
Stage 3 → Emergency contacts notified
          + Admin room broadcast (guardian.escalated)
          + GuardianActivity log: CHECKIN_ESCALATED
       ↓  (still no response)
Stage 4 → SOS recommendation sent to rider
          + GuardianActivity log: SOS_RECOMMENDED
          [Architecture only — no auto-trigger]
```

## Socket.IO Events

| Event | Direction | Description |
|---|---|---|
| `guardian.invited` | Server → Invitee | New invitation received |
| `guardian.accepted` | Server → Rider | Guardian accepted |
| `guardian.rejected` | Server → Rider | Guardian rejected |
| `guardian.removed` | Server → Guardian | Removed from rider's guardians |
| `guardian.started` | Server → Guardian | Session started |
| `guardian.checkin` | Server → Guardian | Check-in acknowledged |
| `guardian.missed` | Server → Rider/Guardian | Check-in missed (stage 1 & 2) |
| `guardian.escalated` | Server → Room/Rider | Stage 3 & 4 escalation |
| `guardian.completed` | Server → Guardian | Session ended |
